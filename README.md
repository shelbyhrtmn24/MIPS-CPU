# MIPS‑CPU: 32‑Bit Pipelined MIPS CPU with Test Cases
# Shelby Hartman

Verilog-based implementation of a 32-bit 5-stage-pipelined MIPS CPU, complete with test benches for functional validation.

---

##  Overview

This project presents a modular, five-stage pipelined CPU that follows the classic MIPS architecture. The CPU executes instructions across the following stages:

1. **Fetch (F)** – Retrieves instructions from instruction memory.
2. **Decode (D)** – Decodes the instruction and reads source operands from the register file.
3. **Execution (X)** – Performs ALU operations, calculations, and computes branch targets.
4. **Memory Access (M)** – Reads or writes data to/from data memory.
5. **Write‑Back (W)** – Writes results back to the register file.

Key features include hazard detection and resolution (e.g., stalls, bypassing), and support for a subset of MIPS instructions such as arithmetic operations, memory loads/stores, branches, and jumps. The design is heavily inspired by canonical texts on computer architecture.

Built-in python-based autotester allows users to write custom assembly, run them, and compare expected and actual results.

##  Repository Structure (Essential Remaining Folders)

Below is a breakdown of the core directories and their contents:

### `/main/proc/`  
Contains Verilog modules that form the backbone of the CPU:

- `processor.v` - The top-level module, integrating all stages into a unified pipeline.
- `pc_controls.v` - Contains stalling and branching logic for branch and jump instructions.
- `bypass_controls.v` - Stalling and bypassing logic for hazard mitigation. 
- `/alu-main/` - Holds onboard ALU and README.md file describing design and functionality. Also holds code for ALU component modules, namely MUX's, shift register, and a fast-adder module. 
- `/multdiv/` - Holds multdiv unit files and README.md file describing design. 
- `/reg_file/` - Contains insns memory register file and README with module description. 

### `/test_files/`  
Houses test files separated by type:

- `/assembly_files/` Assembly test files.
- `/mem_files/` - `.mem` files for pre-filling CPU data memory. 
- `/output_files/` - Saves outputs generated by CPU running each test.  
- `/verification_files/` - Stores expected CPU test for each corresponding assembly test file. 

### `/helper_scripts/`, `/assembler-python-version/`, and `/html_reports/`
- Provide testing capability, see Tester_README.md for information on using the autotester.

##  Getting Started

1. **Prerequisites**  
   - Verilog simulation tool (e.g., Icarus Verilog, ModelSim).
   - Waveform viewer (e.g., GTKWave) for signal analysis.
   - MIPS assembler or toolchain (if running assembly-based tests).

2. **Simulating the CPU**  
   Use the provided testbench to simulate CPU execution:

   ```bash
   iverilog -o cpu_tb.vvp test/cpu_tb.v src/*.v
   vvp cpu_tb.vvp
   ```

   Launch GTKWave to inspect internal signals:

   ```bash
   gtkwave wave.vcd
   ```

3. **Running Tests**  
   Compare simulation outputs to expected results to verify correctness. See Test_README.md for autotester instructions.

##  Instruction Set & Features

This CPU supports a representative subset of MIPS instructions, including:

- **R-type**: `add`, `sub`, `and`, `or`, `sll`, `sra`, `mul`, `div`
- **I-type**: `addi`, `lw`, `sw`, `beq`, `blt`, `bne`.
- **J-type**: `j`, `jal`, `jr`.

Key architectural features:

- Five-stage pipelined design.
- Hazard detection and forwarding to reduce stalls.
- Modular design conducive to extension (e.g., exception handling, CP0, co-processors).
