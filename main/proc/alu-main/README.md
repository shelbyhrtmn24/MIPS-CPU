# ALU
## Shelby Hartman

## Description of Design

The ALU is split up into six modules, one for each operation. The ALU runs every operation for operand A and operand B every time, and uses a MUX with the ALU opcode as the selector to decide which result to output as data_result. The bitwise_and and bitwise_or operations are just done using 32 and gates/or gates, respectively. Shift left and shift right are done using barrel shifters. A larger shift_left_logical.v and shift_right_arithmetic.v module take in both operands, as well as the shift amount, and uses a connected sixteen-bit, eight-bit, four-bit, two-bit, and one-bit shifter, each given its own module. The shift amount is broken up, with each bit determining if one of the smaller shifts occurs. For instance, the most significant bit determines if the sixteen-bit shift occurs. 

Addition and subtraction are done by a two-level CLA. This is split across two modules: full_cla.v and eight_bit_cla.v. Each eight-bit cla calculates generate and propagate functions for each bit position, then calculates the carry-in for each bit. All one-bit additions are done, and an eight-bit sum, as well as G and P bits are output. The full_cla module uses four of these eight-bit cla's to do 32-bit addition, and uses the global G and P signals generated by each cla block to calculate the carry-in for the next one. Two full_cla instances are used in the ALU, one that takes in operand A and operand B as-is, and one that takes in a bitwise inversion of operand B, as well as an initial carry-in, to do subtraction. 

The main ALU also determines the isNotEqual, overflow, and isLessThan signals. isNotEqual is determined with a 32-input or gate using the output of subtraction. Overflow is determined by checking if the most-significant bits of operands A and B match and if the most-significant bit of the result is different through a series of and, or, and not gates. Whether to use B or -B, as well as whether to use the result of addition or subtraction, is determined by a 2-input MUX with the least-significant bit of the opcode as a selector. isLessThan is determined by checking the most-significant bit of the subtraction output compared with the overflow output. If A[31] and B[31] are both 0's and result[31] is 1, then it is considered a positive overflow. A negative overflow is the opposite. The logic equation: data_sub[31]!pos_ovf + !data_sub[31]neg_ovf determines isLessThan.
