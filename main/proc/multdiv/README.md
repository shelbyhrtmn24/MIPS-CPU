# Multdiv
## Shelby Hartman

## Description of Design

The multiplier implements a modified Booth's algorithm with a mod-16 counter. When the ctrl_MULT signal is high, the counter and the 65-bit register that stores the running product are both set to 0. On each clock cycle, the data stored in the register is read, and the last 3 bits are sent into a control logic module, which generates a series of control signals: ctrl_shift, ctrl_add, ctrl_sub, and ctrl_zeroin. These control signals feed into a series of MUX's that determine if the multiplicand (data_operandB) should be shifted left, inverted, or replaced with 0. The result then feeds into a CLA adder along with the first 32-bits of the register output. The product is then concatenated with the 33 least-significant bits of the register output, and the whole string is arithmetically right-shifted by two. This provides the final product for the clock cycle, which is written into the register. If the mod-16 counter is at 0000, the register read data is replaced with an initial output of the form {32'b0, data_operandA, 1'b0}. If the counter is at 1111, then the right-shifted product that writes into the register at the end of the clock cycle is output by the multiplier as the result, and a signal indicating that the result is ready turns on. An exception signal also goes high if, when data_resultRDY is high, the 33 most-significant bits of the result don't match. 

The divider implements a restoring division algorithm, where data_operandA is the dividend and data_operandB is the divisor. If either input to the divider is negative, it is changed to be positive, and logic also checks if only one of the two operands is negative, at which point the quotient will also be sign-corrected. A mod-32 counter times the entire module. On each clock cycle, the data read out of a 64-bit register is left-shifted by 1. The divisor is then subtracted from the 32 most-significant bits of the register output, and the most-significant bit of the result is used as a control signal, called sub_bad. If it's a 1, the LSB of the register read data is replaced with a 0 and is concatenated with the read data from before the test subtraction was done. If the control signal is a 0, then the LSB of the register output is replaced with a 1 and the 32 MSBs are replaced with the result of the test subtraction. This new 64-bit signal is then written into the register. If the counter reads 000000, then the input to the register is set to an initial input of {32'b0, dividend}. When the counter reaches a value of 100000, then the data_resultRDY signal is set to high and the last 32 bits of register write data are assigned as the data_result. If the divisor is 0, then an exception is thrown and the result is set to 0. 

The multdiv module mediates the control signals initiating multiply and divide operations and decides which module's output should be the global data_result. Whenever a ctrl_MULT or ctrl_DIV signal is set to high, the reset signal for the respective operation module is set to high. A DFF then stores what the last operation called was, where 1 = multiplication and 0 = division, using ctrl_MULT | ctrl_DIV as the enable signal. The output of this DFF then becomes the select bit for a series of MUXes which decide whether the output result, ready, and exception signals of the multiplier or divider should be propagated.
